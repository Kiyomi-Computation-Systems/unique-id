* unique-id

[[https://github.com/Kiyomi-Computation-Systems/unique-id/actions/workflows/ci.yml][https://github.com/Kiyomi-Computation-Systems/unique-id/actions/workflows/ci.yml/badge.svg]]

UUIDs for R6RS Scheme: version 4, random, and version 7, ordered by time, as
[[https://www.rfc-editor.org/rfc/rfc9562][RFC 9562]] defines them.

#+begin_quote
✨ *AI Disclosure:* LLMs are used extensively in the planning and development of this project.
#+end_quote

** Features

- *Text and bytes.* Read the 36-character form in either case, write it in
  lower case, and turn an id into its 16 bytes and back.
- *Version 4 and version 7.* Make either from bits you supply, or from a
  generator.
- *Ids that sort by time.* One generator's v7 ids increase: within one
  millisecond, when the clock steps back by up to 10 seconds, and when the
  counter runs out. A clock more than 10 seconds behind the last id resets it.
- *Look inside.* An id's version, its variant, and a v7 id's timestamp.
- *Compare and hash.* =uuid=?=, =uuid<?=, =uuid-hash= for hashtables, and a
  keyed hash for tables of ids that others send you. The nil and max ids.
- *Plain R6RS.* Tested on Chez Scheme and Guile. Only ~(unique-id system)~
  needs more: SRFI-19 for the clock, and ~/dev/urandom~.

The first release is 0.1.0. The names below may change in any release before
1.0, and [[file:CHANGELOG.md][CHANGELOG.md]] says what each release has.

** Quick start

#+begin_src scheme
(import (rnrs) (unique-id) (unique-id generator) (unique-id system))

(define gen (make-system-uuid-generator))

(define id (generate-v7 gen))
(uuid->string id)               ; 36 characters, lower case
(uuid-version id)               ; => 7
(uuid-v7-timestamp id)          ; => milliseconds since 1970

(uuid<? id (generate-v7 gen))   ; => #t: the next id is greater

(string->uuid "not an id")      ; => #f

(define nodes (make-hashtable uuid-hash uuid=?))
(hashtable-set! nodes id 'root)

;; ids that clients send: a hash with a secret key
(define seen (make-hashtable (make-system-uuid-hash) uuid=?))
#+end_src

An id is a record. Compare ids with =uuid=?=, not =equal?=, which Schemes
answer differently for records.

~(unique-id)~ alone, with the bits you choose:

#+begin_src scheme
(import (rnrs) (unique-id))

(define id (string->uuid "017F22E2-79B0-7CC3-98C4-DC0C0C07398F"))
(uuid->string id)        ; => "017f22e2-79b0-7cc3-98c4-dc0c0c07398f"
(uuid-variant id)        ; => rfc9562
(uuid-v7-timestamp id)   ; => 1645557742000

;; milliseconds, a 12-bit counter, 8 random bytes
(make-uuid-v7 1645557742000 #xCC3 (make-bytevector 8 #x18))
;; 16 random bytes
(make-uuid-v4 (make-bytevector 16 #x91))
#+end_src

- =string->uuid= reads only the 36-character form. Any other string gives
  =#f=; anything but a string raises.
- A variant is =ncs=, =rfc9562=, =microsoft= or =future=. =uuid-version= is
  =#f= for every variant but =rfc9562=.
- A procedure given the wrong kind of argument raises an assertion violation
  that names it.
- =uuid-hash= has no secret key, so anyone can make ids that share a hash. For
  a hashtable keyed by ids a client sends, use =(make-uuid-hash key)=, with 8
  secret bytes, or =(make-system-uuid-hash)=, which draws them for you.

A generator, from a clock and a source of random bytes that you give it:

#+begin_src scheme
(import (rnrs) (unique-id) (unique-id generator))

;; CLOCK answers Unix milliseconds; ENTROPY, given N, answers N random bytes.
(define gen (make-uuid-generator clock entropy))
(generate-v4 gen)
(generate-v7 gen)   ; greater than this generator's last v7 id
#+end_src

- One generator's v7 ids increase: when the clock repeats, when it falls up
  to 10 seconds behind the last id, and when you ask for thousands in one
  millisecond, which moves the ids ahead of the clock.
- That order is one generator's alone. Ids from two generators, or from before
  a restart, may interleave.
- A clock more than 10 seconds behind the last id resets its generator: the
  next id takes the clock's time, and sorts below the last one. The clock can
  fall, or the ids can run that far ahead of it, at millions a second.
- The clock and the random source must not call their own generator.

~(unique-id system)~ supplies the clock and the random bytes:

#+begin_src scheme
(import (rnrs) (unique-id) (unique-id generator) (unique-id system))

(system-clock)                  ; => Unix milliseconds, from SRFI-19's time-utc
(system-entropy 16)             ; => 16 bytes from /dev/urandom
(make-system-uuid-generator)    ; a new generator over the two
(make-system-uuid-hash)         ; a new keyed hash, its key from /dev/urandom
#+end_src

- Every call to =system-entropy= that reads opens ~/dev/urandom~ afresh, so a
  forked process never repeats its parent's random bytes.
- Each generator and each hash is new. Give each thread its own generator: one
  generator is not safe to share.
- A keyed hash that is given something other than an id raises an assertion
  violation that names =make-uuid-hash=.

Three libraries:

- ~(unique-id)~ :: ids themselves. No clock, no randomness: you pass in every
  bit that varies.
- ~(unique-id generator)~ :: makes ids from a clock and a source of random
  bytes that you give it.
- ~(unique-id system)~ :: the system's clock and ~/dev/urandom~, and a
  generator and a keyed hash made of them.

** Use it

unique-id is three R6RS libraries under ~src/~. Clone a release, and put ~src/~
on your Scheme's library path:

#+begin_src sh
git clone --branch v0.1.0 https://github.com/Kiyomi-Computation-Systems/unique-id.git
#+end_src

On Chez, ~(unique-id system)~ also needs SRFI-19, from [[https://github.com/arcfide/chez-srfi][chez-srfi]]: in the
clone, ~make submodules deps~ puts it in ~build/scheme-libs~. Guile has its own.
[[file:docs/getting-started.md][Getting started]] gives the commands for both Schemes.

** Build and test

You need Linux or macOS, on x86-64 or arm64, with:

- Chez Scheme, as ~scheme~ or ~chez~ on ~PATH~, or named by ~CHEZ~. CI builds
  10.4.1; 10.4.0 runs the suites too.
- Guile 3, as ~guile~ or ~guile-3.0~ on ~PATH~, or named by ~GUILE~. CI
  installs Ubuntu 24.04's 3.0.9; 3.0.11 runs the suites too.
- GNU make, and GNU ~timeout~ (~brew install coreutils~ on macOS).

On Chez, the suites and ~(unique-id system)~ take SRFI-64 and SRFI-19 from
[[https://github.com/arcfide/chez-srfi][chez-srfi]], pinned under ~vendor/~. Guile has its own.

#+begin_src sh
git clone https://github.com/Kiyomi-Computation-Systems/unique-id.git
cd unique-id
make submodules   # clones chez-srfi at its pin
make test         # the checks, then every suite on Chez and on Guile
#+end_src

~make help~ lists every target. ~make reference~ writes ~docs/reference.md~
from the signature comments in ~src/~, and ~make test~ fails while it is out of
date. ~make site~ renders ~docs/~ as HTML into ~build/site/~, and ~make
check-site~ checks its every page, link and anchor; both need ~libcmark-gfm~
(~apt install cmark-gfm~ or ~brew install cmark-gfm~) and fetch chez-cmark-gfm
once.

** Credits

The formats, and the test vectors the suites check, are from [[https://www.rfc-editor.org/rfc/rfc9562][RFC 9562]],
/Universally Unique IDentifiers (UUIDs)/, by K. Davis, B. Peabody and P. Leach.
The generator's 10-second allowance for a clock that steps back follows
[[https://github.com/LiosK/uuidv7][LiosK's uuidv7]] and its Rust port, [[https://docs.rs/uuid7][uuid7]]. The keyed hash is HalfSipHash-2-4,
from Jean-Philippe Aumasson and Daniel J. Bernstein's SipHash; its test vectors
come from the [[https://github.com/veorq/SipHash][SipHash reference implementation]].
